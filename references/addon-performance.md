# 插件性能排查手册

WoW 的插件运行在**主线程**上，与游戏渲染共用同一个线程。**一个写得很烂的插件可以让你在团本里掉 30 帧，而 GPU 占用率看起来完全正常。**

---

## 一、判断"是不是插件在搞鬼"的信号

| 信号 | 说明 |
|---|---|
| GPU 占用只有 50–70%，但帧数很低 | **典型插件 / CPU 瓶颈** |
| 野外帧数正常，一进团本暴跌 | 人多 → 插件要处理的事件暴增 |
| 掉帧有周期性（每隔几秒一顿） | 某个插件在定时做重活（如 Details 的窗口更新、WA 的定时扫描） |
| 关闭全部插件后帧数立刻回升 | 已确认，进入二分排查 |
| 帧时间曲线有规则的尖峰 | 某插件的 OnUpdate 或定时扫描 |
| 打开某个面板（如 Details、WA 配置）时明显卡 | 该插件本身开销大 |

---

## 二、基准排查流程（二分法）

### Step 0 — 建立基线

1. **完全退出游戏**
2. 在角色选择界面左下角点 **插件（AddOns）**，**全部取消勾选**（或直接把 `Interface/AddOns` 临时改名）
3. 进入游戏，跑 **Phase 5 的三个场景**，记录基线数据
4. 这个数字就是"没有插件时你的机器能做到什么程度"

> 如果连基线都不达标（比如团本还是只有 40 帧），说明问题**不在插件**，回到 `benchmark-bottleneck.md` 查 CPU / 内存 / 设置。

### Step 1 — 分批开启

1. 把插件按"嫌疑度"分成 4 批：
   - 第 1 批：**战斗信息类**（WeakAuras、Details、DBM/BigWigs、Plater）
   - 第 2 批：**界面框架类**（ElvUI、Bartender、Skins、各种美化）
   - 第 3 批：**功能便利类**（背包、地图、拍卖、采集、聊天）
   - 第 4 批：**其他 / 小工具**
2. 每开一批，跑一遍团本或木桩场景，记录 Average / Min / 1% Low
3. **哪一批开上去后掉帧明显 → 问题在这一批**

### Step 2 — 批内二分

在锁定的批次内，把插件再对半拆分，重复开启-测试，直到定位到单个插件。

> 4 批 × 各约 5 个插件，通常 **5–7 轮测试** 就能锁定元凶。

### Step 3 — 元凶处理

- 换替代品（如 Details 换 Skada，WA 换轻量提醒）
- 降级 / 简化配置（见下节各插件专项）
- 按场景禁用（团本才开，其余时间关）
- 实在不行就删

## 三、重点插件专项

### WeakAuras（头号嫌疑）

**为什么慢**：
- 每个 Aura 都在 OnUpdate / 事件回调里跑 Lua
- 复杂 Trigger（尤其是自定义 Lua 函数、TSU）代价极高
- 大量 Aura 同时显示时，每帧都要计算位置、动画、进度条
- 从别人那里导入的"整包 WA"常常包含几十个冗余或冲突的 Aura

**排查与优化**：
1. 打开 WA 的 **性能监视**：`/wa` → 右上角 **Show Performance**，或输入 `/wa p`
2. 按 **每帧耗时（ms）** 排序，看哪些 Aura 最贵
3. 常见优化动作：
   - 删除重复的、已过期的、与当前专精无关的 Aura
   - 把"常驻显示"改为"满足条件才显示"（Load 条件写严格）
   - 禁用不必要的动画、发光、自定义进度动画
   - 把多个小 Aura 合并成一个分组（分组本身也有开销，但通常低于散装）
   - **用 Load 条件限制**：只在团本 / 只在特定 Boss / 只在战斗中加载
4. 极端情况：导出 WA 字符串备份后，清空重装有必要的部分

**经验阈值**：整个 WA 每帧耗时 **超过 1ms** 就值得整治；**超过 3ms** 在团本里会明显感觉到。

---

### Details!（伤害统计）

**为什么慢**：
- 实时采集并处理每一次战斗事件（COMBAT_LOG_EVENT_UNFILTED 是 WoW 最密集的事件）
- 多窗口 = 多份数据处理
- 皮肤、动画、滚动更新持续消耗

**排查与优化**：
1. 团本中**只保留 1 个窗口**
2. `/details` → 性能相关：
   - 关闭 **"Update Interval" 过高** 的刷新（适当调大刷新间隔）
   - 关闭不必要的 **动画 / 滚动效果**
   - 关闭 **数据收集范围**（只收集当前区域 / 关闭"记录所有战斗"）
3. 关闭 **插件同步** 与跨玩家数据请求（团本中会带来网络与 CPU 双重负担）
4. 替代品：Skada（更轻量）、TinyDPS（极简）

---

### ElvUI（界面框架）

**为什么慢**：
- 接管了大量默认 UI 的渲染逻辑
- 单位框体（UnitFrame）在团本中要处理 40 个玩家的状态更新
- 各种美化、边框、阴影、动画累积开销

**排查与优化**：
1. 团本中**关闭团队框体的美化特效**（阴影、发光、渐变边框）
2. 降低 **单位框体更新频率**
3. 关闭不必要的模块（聊天美化、背包美化、地图美化中你用不到的部分）
4. 关掉 **ElvUI 的"高效模式"之外的额外动画**
5. 检查是否有额外的 Skin 插件（如 AddOnSkins）叠加，Skin 插件是常见隐形开销源

---

### Plater（姓名板）

**为什么慢**：
- 每个姓名板都要独立渲染、更新光环（Aura）与施法条
- 团本中同时存在 30+ 个姓名板，光是遍历光环列表就很贵
- 自定义脚本（Mod / Scripts）每帧执行

**排查与优化**：
1. 团本中**关闭友方姓名板**（只显示敌人）
2. 限制**显示的光环数量**（从 10 个降到 4–6 个）
3. 关闭 **姓名板堆叠（Stacking）** 或降低其更新频率（堆叠计算很贵）
4. 检查是否加载了第三方 **Plater 脚本/Mod**，逐个禁用测试
5. 缩小**姓名板显示距离**（远处的不渲染）

---

### DBM / BigWigs（Boss 预警）

**为什么慢**：
- 本身通常不算重，但**加载了全部模块**时会有基础开销
- 大量计时条 + 特殊警告的动画 + 音效

**排查与优化**：
1. 两者**只装一个**，不要同时装 DBM 和 BigWigs
2. 禁用不需要的模块（旧版本 Boss、不打的副本）
3. 团本中关闭不必要的**特殊警告动画 / 全屏闪光**
4. 关闭 DBM 的 **"Show All Timers"** 之类冗余显示

## 四、其他常见隐形开销

| 类型 | 说明 |
|---|---|
| **背包类插件**（Bagnon、ArkInventory 等） | 每次物品变动都重排整个背包，团本中拾取频繁时开销明显 |
| **地图类插件** | 持续渲染世界地图图层 |
| **拍卖/经济类插件**（TSM） | 数据量巨大，扫描时必然卡顿 |
| **聊天美化 / 过滤插件** | 团本聊天刷屏时处理每条消息 |
| **Skin 插件** | 给每个 UI 元素套皮肤，累积开销 |
| **过期/未更新插件** | 报错（Lua Error）会严重拖慢性能——**打开 Lua 错误显示，看是否有刷屏报错** |

**必做检查**：
```
/console scriptErrors 1
```
进团本看是否有 Lua 错误刷屏。**持续报错的插件会严重拖慢帧数**，这是最容易被忽略的性能杀手。

## 五、插件规模扫描

```powershell
powershell -ExecutionPolicy Bypass -File "scripts/scan-addons.ps1" -WowPath "<WoW根目录>"
```

输出按体积排序的插件列表，并标注常见高开销插件。体积大 ≠ 一定慢，但是很好的排查起点（尤其是材质包巨大、模块数量异常的插件）。

## 六、排查结论输出格式

```
基线（全关插件）：团本 Avg 78 / Min 52 / 1% Low 46
第1批后：       团本 Avg 71 / Min 41 / 1% Low 34   ← 掉 12
第2批后：       团本 Avg 70 / Min 40 / 1% Low 33   ← 掉 1
第3批后：       团本 Avg 69 / Min 39 / 1% Low 32   ← 掉 1
第4批后：       团本 Avg 69 / Min 39 / 1% Low 32   ← 掉 0

→ 问题在第 1 批。批内二分：
   开 WA：        Min 44 / 1% Low 36
   开 WA+Details：Min 41 / 1% Low 34   ← Details 贡献 3
   逐项禁用 WA 分组后：Min 50 / 1% Low 43

结论：WeakAuras 中「XX 分组」每帧耗时 2.8ms，为首要元凶。
建议：为该分组设置 Load 条件（仅在团本战斗中加载）。
```
