# 基准测试方法与瓶颈判定

---

## 一、三个必测场景

**每次调整后都必须测这三个。只测一个场景得出的结论是无效的。**

| # | 场景 | 时长 | 测什么 | 为什么 |
|---|---|---|---|---|
| 1 | **主城**（奥格瑞玛 / 暴风城 / 瓦德拉肯） | 2–3 分钟站桩 + 飞行绕一圈 | 玩家密度压力、加载与显存压力 | 主城是唯一能复现"大量玩家 + 大量插件 + 大量 UI 更新"的稳定场景 |
| 2 | **大秘境战斗** | 一次完整 AOE 波次 + Boss | 粒子与法术密度峰值 | 中等密度战斗的典型负载 |
| 3 | **团本 / 世界 Boss** | 一次完整开怪 | **最关键**：1% Low 与最低帧 | 这是用户的真实痛点场景，也是优化的成败标准 |

**测试要求**：
- 每次测试**同样的路线、同样的动作**，保证可比性
- 每次至少测 **2 遍**，取第二次（第一遍常有加载/着色器编译干扰）
- 测试期间**不做其他操作**（不切窗口、不聊微信）

---

## 二、必记字段

| 字段 | 怎么读 | 判读 |
|---|---|---|
| **Average FPS** | Afterburner / CapFrameX | 参考值，**不是主要指标** |
| **Minimum FPS** | Afterburner | 最低瞬时帧，看有没有跌破可接受线 |
| **1% Low** | Afterburner / CapFrameX | **核心指标**：最差的 1% 帧的平均值。它代表"你能感觉到的卡顿程度" |
| **GPU Usage %** | Afterburner | **瓶颈判定的第一依据** |
| **GPU Temperature** | Afterburner | 看是否撞温度墙降频（4060 Ti 通常 65–75°C 正常） |
| **GPU VRAM used** | Afterburner / nvidia-smi | 是否接近显存上限 |
| **CPU 主线程占用** | 任务管理器 → 详细信息 → Wow.exe → 右键"转到详细信息" → 看哪个线程接近 100% | WoW 是主线程依赖，看是否有单线程跑满 |

**推荐工具**：
- MSI Afterburner + RivaTuner Statistics Server（最常用，可记录 1% Low、帧时间曲线、GPU/CPU 全参数）
- CapFrameX（更专业的帧时间分析，出 1% Low / 0.1% Low 与帧时间分布）
- WoW 内置：`/frametimes` 可显示实时帧时间图

## 三、瓶颈判定规则

### 规则 1：GPU 长时间 95–100% → GPU 瓶颈

**含义**：显卡已经跑满，帧数上不去是显卡的锅。

**对策（按顺序）**：
1. 降低 **Shadow Quality**
2. 关闭 **Ray Traced Shadows**（若还开着）
3. 降低 / 关闭 **SSAO**
4. 降低 **Particle Density**
5. 降低 **View Distance / Environment Detail**
6. 最后才考虑 **Render Scale → 95% / 90%**

**注意**：不要降 Texture Resolution——它主要吃显存，对 GPU 算力瓶颈帮助有限却明显伤画质。

---

### 规则 2：GPU 只有 50–70%，但 FPS 很低 → CPU / 主线程 / 插件瓶颈

**含义**：显卡在等 CPU 干活。这是 **RTX 4060 Ti 跑 WoW 最常见的状况**。

**对策（按顺序）**：
1. **排查插件**（见 `addon-performance.md`）——这是第一优先级
2. 降低 **Spell Density** → Essential
3. 降低 **Ground Clutter**（绘制调用大户）
4. 检查 **CPU 温度与降频**（是否撞温度墙、是否降频）
5. 检查 **内存频率**（是否开了 XMP/EXPO、是否双通道）
6. 检查 **后台程序占用**
7. 检查 **是否有 Lua 报错刷屏**

**关键提醒**：这种情况下继续砍画质（降阴影、降分辨率）**基本没用**——因为瓶颈不在 GPU。

---

### 规则 3：野外 FPS 高但团本 FPS 暴跌 → CPU + 插件 + Spell Density

**含义**：人一多，CPU 要处理的单位状态、事件、法术特效呈指数增长。

**对策（按顺序）**：
1. **Spell Density → Essential**（单项收益最大）
2. **排查插件**：WeakAuras、Details、Plater 在人多时开销暴增
3. **Particle Density** 降一档
4. 关闭 **友方姓名板**
5. 检查 **CPU 主线程**是否被单线程跑满
6. 检查 **内存**：团本数据量大，内存带宽不足会放大问题

---

### 规则 4：帧数不低但明显卡顿 → 帧时间抖动

**含义**：平均帧数看着还行，但帧与帧之间的间隔忽长忽短，主观感受就是"卡"。

**对策**：
1. 看 **帧时间曲线**（frametime graph）是否有规律尖峰
2. 有规律尖峰 → 某插件的定时扫描（Details 更新、WA 定时 Trigger）
3. 无规律尖峰 → 后台程序、磁盘 IO、显存换页
4. 检查 **显存是否接近上限**（换页会造成大尖峰）
5. 检查是否有 **Lua 报错刷屏**
6. 尝试 **锁帧**（Max FPS = 刷新率−3），往往能显著平直化帧时间

---

### 规则 5：GPU 显存接近上限 → 显存瓶颈

**症状**：帧数骤降（不是缓慢下降）+ 明显卡顿 + 贴图弹出 + GPU 占用反而下降

**对策（按顺序）**：
1. 关掉 **后台浏览器**（尤其开了硬件加速 + 多标签）
2. 降低 **Max Background FPS**
3. 减少 **插件材质包**
4. 最后才考虑 **Texture Resolution 降一档**

---

## 四、迭代流程

```
调整 → 测三场景 → 判瓶颈 → 回到变更计划（只改一组变量）→ 再测
                                    ↑                        |
                                    └──────── 最多 3 轮 ────────┘
```

**每轮只改一组变量**，否则无法归因。改完立刻测，测完立刻记。

3 轮之后若仍不达标，说明存在**硬件层面的硬限制**（例如 CPU 单核性能不足、内存单通道、显示器刷新率设错），此时应如实告知用户并给出硬件层面的建议，而不是继续折腾软件设置。

## 五、什么算"优化成功"

| 指标 | 成功标准 |
|---|---|
| **1% Low** | 团本场景中提升 ≥ 15%，或稳定在 显示器刷新率的 50% 以上 |
| **最低帧** | 团本开怪瞬间不再跌破 30 帧 |
| **帧时间曲线** | 尖峰明显减少，曲线平直 |
| **主观** | 团本走位、打断、躲技能不再有"粘滞感" |

**平均 FPS 提升但 1% Low 没变 = 优化失败。** 这是最常见的自欺欺人陷阱。
